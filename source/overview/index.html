Source Architecture & Memory Model

Complete breakdown of Mizar's internal subsystems and memory contracts.

Repository Layout

src/
├── algo/      # Pure, self-contained algorithms & data structures
│   ├── arena.h/.c    # Chunk-based bump allocator
│   ├── strview.h     # Zero-copy bounds-checked string slices
│   ├── siphash.h/.c  # 64-bit SipHash-1-3 collision defense
│   ├── hashmap.h/.c  # Open-addressing hash table with arena support
│   ├── radix.h       # O(k) prefix tree router
│   ├── ringbuf.h/.c  # SPSC circular byte stream buffer
│   ├── utf8.h/.c     # DFA UTF-8 decoder & code point validator
│   └── lru.h/.c      # O(1) LRU cache with SipHash & DLL
├── server/    # Non-blocking HTTP socket engine & router
├── core/      # Buffers, URL helpers, tagged results, SHA256
├── view/      # Declarative HTML5, SVG, MathML, and JS DSL
├── ssg/       # Static site generator engine
└── ui/        # Standard pre-styled UI components and icons

The Per-Request Arena Contract

Traditional C web servers suffer from memory fragmentation and leaks due to thousands of individual malloc calls for headers, cookies, and parameters. In Mizar, every incoming request initializes a dedicated MzArena. All request strings and hash map bucket arrays allocate contiguously inside this arena. When the request completes, mz_req_free() destroys the entire arena in a single pointer adjustment. Zero leaks.
